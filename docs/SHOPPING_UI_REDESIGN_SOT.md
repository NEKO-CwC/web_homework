# Minimal Mall 商城化 UI 改造唯一事实文档

## 1. 文档定位

本文档是 Minimal Mall 后续 UI、导航、页面结构、角色体验改造的唯一事实来源。

`docs/PRD.md` 继续作为业务功能、数据能力、权限规则和课程验收范围的权威文档。凡涉及 UI 信息架构、角色入口、导航展示、页面布局、前台购物体验、商家/管理员后台呈现方式时，以本文档为准。

本次设计方向由用户确认：采用折中方案，但偏向真实商城。系统必须保留顾客、商家、管理员三类课程功能，但默认体验应像一个正常购物网站，而不是把三类角色功能同时摊开给所有人。

## 2. 现状问题与证据

当前项目功能较完整，但 UI 信息架构偏课程验收台，不符合购物网站常见体验。

已确认的本地证据：

| 问题 | 证据 |
| --- | --- |
| 三种角色入口同时暴露 | `apps/storefront/app/components/AppNavigation.tsx` 中 `createNavGroups` 固定返回“顾客前台 / 商家中台 / 管理员后台”三组导航 |
| 所有页面共用同一套全角色布局 | `apps/storefront/app/layout.tsx` 将全部页面包裹在 `AppNavigation` 中 |
| 首页存在课程说明式文案 | `apps/storefront/app/page.tsx` 出现 “Banner seed”、“管理员保存配置”、“购物主链路”、“页面状态覆盖”等验收说明 |
| 权限体验依赖 403 兜底 | 商家和管理员页面通过 `AccessDenied` 阻止访问，但入口仍在全局导航中可见 |

结论：本次不是简单换色或美化，而是要调整产品信息架构，让用户默认进入购物场景，并按身份进入对应工作台。

## 3. 核心设计原则

### 3.1 商城第一

默认首页、默认导航、默认搜索、默认内容都服务于购物行为。用户打开 `/` 时，第一感知必须是在线商城，而不是角色功能演示面板。

### 3.2 角色后台按身份和路径隔离

顾客前台、商家中心、管理员后台可以存在于同一个 Next.js 应用内，但不能共享同一个全角色导航。

- 前台只展示购物相关入口。
- 商家中心只展示商家经营入口。
- 管理员后台只展示平台治理入口。
- 无权限 URL 直接访问时才显示权限引导。

### 3.3 保留课程验收能力，但不把验收痕迹放在前台

所有课程要求功能仍需可访问、可演示、可测试。前台页面不得出现 `seed`、`功能覆盖`、`页面状态覆盖`、`管理员同步`、`403` 作为主要用户文案。

### 3.4 低风险优先，逐步全量改造

改造分三期推进。Phase 1 先解决最大违和点：全角色导航和课程化首页。Phase 2 强化购物链路交互。Phase 3 完成全量角色壳、页面体验、测试和视觉验收。

## 4. 目标体验模型

### 4.1 游客

游客进入商城后可浏览首页、搜索商品、筛选分类、查看商品详情。

游客不应看到商家商品管理、商家订单、管理员审核、系统维护等后台入口。需要登录的操作应显示登录引导，而不是冷冰冰的 403。

游客前台可见入口：

- 首页
- 分类 / 搜索
- 商品详情
- 登录 / 注册
- 购物车入口，点击后引导登录
- 申请开店

### 4.2 顾客

顾客登录后仍停留在购物网站体验中。

顾客前台可见入口：

- 首页
- 分类 / 搜索
- 购物车
- 我的订单
- 评价 / 售后
- 个人资料
- 申请开店
- 退出登录

顾客不应看到商家商品管理或管理员后台入口。

### 4.3 商家

商家可以浏览前台商品，但核心身份入口是“卖家中心”。

商家前台可见入口：

- 首页
- 分类 / 搜索
- 卖家中心
- 店铺资料或账号入口
- 退出登录

商家中心导航只包含：

- 商家首页 / 经营概览
- 商品管理
- 订单发货
- 售后处理
- 店铺资料

如当前账号还没有审核通过的店铺，商家中心应引导其提交开店申请或查看审核状态。

### 4.4 管理员

管理员可以直接进入后台治理页面。管理员后台必须和商城前台视觉区分明显，但不需要营销感。

管理员前台可见入口：

- 首页
- 管理后台
- 账号入口
- 退出登录

管理员后台导航只包含：

- 平台总览
- 商家审核
- 首页广告
- 系统维护

管理员入口不对游客、顾客、商家展示。

## 5. 信息架构

### 5.1 前台商城 Shell

适用路由：

- `/`
- `/products/[id]`
- `/cart`
- `/checkout`
- `/orders`
- `/after-sale`
- `/account`
- `/merchant/apply`

布局要求：

- 使用顶部横向导航，不使用左侧后台侧边栏。
- 顶部包含品牌、分类入口、搜索框、购物车、订单或账号菜单。
- 移动端使用底部或抽屉式导航，不能把三种角色菜单混在一起。
- 商家申请入口可以出现在账号菜单、页脚或首页服务区，但不能压过购物主链路。

首页结构：

1. 真实商城 Hero：促销、精选专题或新品推荐。
2. 分类快捷入口。
3. 精选商品网格。
4. 店铺推荐或服务保障。
5. 轻量商家入驻入口。

首页禁止内容：

- 课程作业说明。
- “seed 数据”说明。
- “页面状态覆盖”展示区。
- “管理员保存后同步”这类内部实现说明。
- 把顾客、商家、管理员三端链路写成首屏主卖点。

### 5.2 商家中心 Shell

适用路由：

- `/merchant`
- `/merchant/products`
- `/merchant/orders`
- 后续新增的 `/merchant/store`、`/merchant/after-sales` 等商家路由

布局要求：

- 使用工作台布局，可以使用左侧导航。
- 左侧导航只展示商家能力。
- 顶部显示店铺名、经营状态、返回商城、账号操作。
- 商品、订单、售后页面以表格、筛选、状态标签和批量操作为主。
- 无店铺或未审核通过时显示开店申请、审核状态、返回商城，而不是只显示 403。

### 5.3 管理员后台 Shell

适用路由：

- `/admin`
- `/admin/merchants`
- `/admin/home`
- `/admin/system`

布局要求：

- 使用后台工作台布局，可以使用左侧导航。
- 左侧导航只展示管理员能力。
- 顶部显示平台状态、返回商城、账号操作。
- 不做商城 Hero，不做营销式大图。
- 重点是指标卡、待办、表格、审计记录、配置项。

### 5.4 权限与入口展示规则

| 当前身份 | 前台是否显示购物入口 | 前台是否显示商家入口 | 前台是否显示管理员入口 | 直接访问无权限后台 |
| --- | --- | --- | --- | --- |
| 游客 | 是 | 申请开店 | 否 | 登录 / 返回商城引导 |
| 顾客 | 是 | 申请开店 | 否 | 申请开店 / 返回商城 / 切换账号 |
| 商家 | 可浏览 | 卖家中心 | 否 | 返回卖家中心 / 返回商城 |
| 管理员 | 可浏览 | 否或弱化 | 管理后台 | 返回管理后台 / 返回商城 |

入口隐藏不能代替服务端权限校验。所有原有权限校验必须继续保留。

## 6. 页面设计准则

### 6.1 前台商城页面

前台页面应该轻、清晰、购物导向。

- 商品卡片包含：图片、店铺、商品名、卖点、价格、库存或售罄状态、加入购物车。
- 商品详情包含：大图、价格、店铺、库存、购买操作、商品说明、服务承诺。
- 购物车包含：商品行、数量修改、小计、合计、结算按钮、空购物车引导。
- 结算包含：地址、商品摘要、虚拟支付方式、确认支付。
- 订单包含：订单状态、商品、金额、虚拟物流、确认收货、评价 / 售后入口。
- 账号页包含：登录、注册、个人资料、默认地址，不展示角色权限教学步骤。

### 6.2 商家中心页面

商家中心应该是经营工作台。

- 首屏优先展示经营指标、待处理订单、待处理售后、商品状态。
- 商品管理优先支持快速筛选、发布、上下架、库存识别。
- 订单管理优先支持待发货、已发货、售后处理、虚拟运单生成。
- 店铺资料作为经营设置，不和商品发布混成一个过长页面。

### 6.3 管理员后台页面

管理员后台应该是治理工作台。

- 平台总览展示关键指标和待办。
- 商家审核页面优先展示申请状态、材料、审核操作、驳回原因。
- 首页广告管理页面展示 Banner 预览、配置表单、上线状态。
- 系统维护页面展示服务状态、配置项、审计记录。

### 6.4 文案规则

面向用户的文案使用产品语言，不使用实现语言。

| 禁止文案方向 | 替代方向 |
| --- | --- |
| seed、mock、fixture | 精选商品、示例商品、当前商品 |
| 功能覆盖、验收、链路演示 | 我的订单、去结算、查看物流、申请售后 |
| 403 无权访问 | 你当前账号不能访问此页面，可返回商城或切换账号 |
| 管理员保存后同步 | 首页内容已更新 |

## 7. 三阶段改造路线

### Phase 1：低风险商城化改造

目标：不大改业务逻辑和数据模型，先让项目第一眼像真实商城。

范围：

- 将全局 `AppNavigation` 改为按路由和身份展示不同导航。
- 前台路由使用顶部商城导航，隐藏商家中台和管理员后台菜单。
- 商家和管理员路由保留工作台式侧边栏，但只显示对应角色菜单。
- 清理首页课程化文案和“页面状态覆盖”展示区。
- 让无权限访问页变成动作引导：返回商城、登录 / 切换账号、申请开店。
- 保留现有路由、Server Actions、数据读取和权限校验。

不做：

- 不拆分应用。
- 不重写业务服务。
- 不引入新的支付、物流或推荐能力。
- 不把所有页面视觉一次性重做。

Phase 1 完成标准：

- 游客打开 `/` 时看不到商家商品管理、商家订单、管理员后台、系统维护入口。
- 首页首屏是商城促销 / 商品发现，不出现课程验收文案。
- `/merchant/*` 页面只显示商家导航。
- `/admin/*` 页面只显示管理员导航。
- 未登录或错误角色直接访问后台时，看到可执行的引导操作，而不是只有 403。
- 现有核心测试通过，至少补充或更新导航相关 E2E 断言。

### Phase 2：购物链路体验强化

目标：让顾客从浏览到售后的主链路更像真实购物网站。

范围：

- 重构首页商品发现区：分类、搜索、精选商品、店铺推荐、服务保障。
- 优化商品详情：购买区、店铺信息、库存状态、服务承诺、返回路径。
- 优化购物车：数量修改、空状态、合计、结算摘要、登录引导。
- 优化结算与虚拟支付：地址、订单摘要、支付反馈、跳转订单。
- 优化订单与售后：状态分组、物流时间线、确认收货、评价和售后入口。
- 优化账号页：登录 / 注册 / 个人资料分区更清楚，移除权限教学感。
- 增加移动端前台导航体验和关键状态反馈。

Phase 2 完成标准：

- 顾客核心链路可在桌面和移动端自然完成：浏览商品 -> 加入购物车 -> 结算 -> 支付 -> 查看订单 -> 确认收货 -> 评价 / 售后。
- 未登录用户在需要登录的购物操作中看到登录引导。
- 所有主要操作有成功、失败、加载或禁用反馈。
- 前台页面不再出现后台或课程验收语境。
- Playwright 覆盖顾客主链路和移动端基本导航。

### Phase 3：全量角色体验与视觉验收

目标：完成最终全量改造成果，三类角色都拥有符合真实产品的独立体验。

范围：

- 建立稳定的三套 Shell：前台商城、商家中心、管理员后台。
- 商家中心拆清楚经营概览、商品管理、订单发货、售后处理、店铺资料。
- 管理员后台拆清楚平台总览、商家审核、首页广告、系统维护。
- 全面清理所有课程说明式文案和只为验收存在的 UI。
- 统一组件状态：表单、按钮、表格、卡片、Toast、空状态、错误状态。
- 完成响应式与可访问性校验。
- 建立 UI 截图验收产物。

Phase 3 完成标准：

- 三种角色入口、导航、页面布局完全按本文档隔离。
- 课程功能完整保留，且从真实产品入口自然触达。
- `390x844`、`768x1024`、`1440x900` 三个视口均无明显文字溢出、遮挡、重叠。
- 顾客、商家、管理员关键路径均有 E2E 覆盖。
- 每个核心页面至少有一张验收截图或等价视觉检查产物。
- `docs/PRD.md` 与本文档不再存在 UI 目标冲突。

## 8. 后续实现约束

任何后续 UI 改造任务必须先确认属于哪个 Phase，并在交付说明中写明：

- 本次改动对应的 Phase。
- 对应本文档中的目标或完成标准。
- 修改了哪些页面、组件和导航规则。
- 验证了哪些角色、路由和视口。
- 哪些内容仍未进入当前 Phase。

不得以“功能还在”为理由保留错误的入口暴露。功能存在和入口可见是两个问题：业务功能必须保留，用户界面必须按身份和场景展示。
